# GAN Face Detector

This is our course project for deep learning. We train classifiers that decide whether a face image is a real photograph or was generated by a GAN. We use the "140k Real and Fake Faces" dataset from Kaggle, in which the real faces come from FFHQ (Flickr-Faces-HQ) and the fake faces were generated by StyleGAN.

## Models

We compare four model families on the same data splits:

- MLP: a fully connected network on flattened pixels, used as a baseline.
- CNN: a convolutional network.
- LSTM: a recurrent network that reads the image as a sequence of rows or patches.
- ViT: a vision transformer.

We also use Grad-CAM to look at which image regions a trained CNN or ViT responds to, and a small Gradio demo to try a trained model on image pairs and single images.

## Layout

```
src/data/      manifest, dataset loading, transforms, data audit, dummy data for testing
src/models/    one file per model family
src/metrics.py
src/train.py
src/evaluate.py
src/compare.py
src/gradcam.py
demo/app.py          Gradio demo
demo/make_backup.py static copy of the demo outputs
results/       one subfolder per model, created when a model is trained
```

Downloaded data goes in `data/` and model weights in `checkpoints/`. Neither is tracked in git.

## Setup

Create a virtual environment and install the dependencies:

```
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS
pip install -r requirements.txt
```

For a CUDA build of PyTorch, follow the install command on pytorch.org for your CUDA version before installing the rest.

## Data

To download the dataset, create an API token on your Kaggle account page and place `kaggle.json` in `~/.kaggle/` (on Windows, `C:\Users\<name>\.kaggle\`). The token stays in your home folder and is never copied into the project. Then run from the project root:

```
kaggle datasets download -d xhlulu/140k-real-and-fake-faces -p data/raw --unzip
```

Find the folder inside `data/raw` that contains `train/`, `valid/` and `test/` (each with `real/` and `fake/`) and build the manifest from it:

```
python src/data/build_manifest.py --root <that folder> --out data/manifest.csv
```

The manifest lists every image with its label (0 = real, 1 = fake) and split. We keep the dataset's own train, validation and test splits. A fixed set of 50 real and 50 fake test images (seed 42) is moved to a separate `demo` split for the demo app and is not part of any reported test metric. The script stops if the same file, or a file with identical content, appears in more than one split.

Before training we run a shortcut audit:

```
python src/data/audit.py --manifest data/manifest.csv
```

It reports image dimensions, colour mode, format and file sizes per class, fits a logistic regression on file size alone and reports its validation ROC-AUC, and saves a grid of sample images to `results/figures/`. A high AUC from file size alone would mean a model could separate the classes without looking at the faces.

For testing the code without the real data, `src/data/make_dummy_data.py` writes a small set of random-noise images in the same layout to `data/dummy/`. It contains no faces and we do not report any result obtained on it.

## Training and comparison

`src/train.py` trains one model on the manifest (`--model cnn`, `cnn_resnet34`, `lstm`, `vit` or `vit_base`; the MLP baseline has its own script, `src/train_mlp.py`). Run the scripts from the project root as modules, for example `python -m src.train --model cnn`. `cnn` is an ImageNet-pretrained Xception from timm and `cnn_resnet34` is an ImageNet-pretrained ResNet-34; both are fine-tuned end to end with a lower learning rate for the backbone than for the new one-logit head. If the pretrained weights cannot be downloaded the code prints a warning and starts from random weights. Every epoch it evaluates on the val split, keeps the checkpoint with the best val ROC-AUC in `checkpoints/<model>/best.pt`, and logs to `results/<model>/log.csv`. At the end it evaluates that checkpoint once on the test split and writes `metrics.json`, `confusion_matrix.png` and `roc.csv` to `results/<model>/`. `--limit N` trains on a class-balanced random subset of N training images; val and test always use the full splits, and `metrics.json` records how many training images were used. `src/evaluate.py` repeats the test evaluation for an existing checkpoint, and `src/compare.py` prints a markdown table of all models in `results/` and saves `results/figures/roc_comparison.png`. `lstm` is a bidirectional two-layer LSTM that reads the image as a sequence of 16x16 raw pixel patches in row-major order, with one linear layer in front and no convolutional layers. The sequence length is (image size / 16) squared, so a smaller `--img-size` such as 128 makes it much shorter than the 224 default; the image size used is stored in `metrics.json` and shown in the comparison table. Training clips the gradient norm for this model. `vit` is an ImageNet-pretrained ViT-Small (patch size 16, 224 px) from timm and `vit_base` is the larger ViT-Base; all layers are fine-tuned with a small learning rate (we start from `--lr 2e-5`), a linear warmup over the first tenth of the training steps, and mixed precision on a GPU. The learning rate follows a cosine decay that is stepped every batch for all models. All models use the same manifest, transforms and metrics code.

## Grad-CAM and demo

`src/gradcam.py` has three commands that take a checkpoint (CNN or ViT): `demo` draws a figure of demo holdout images with heatmap overlays and predictions, `mean` averages the heatmaps over test images of each class (500 per class by default), and `errors` draws misclassified test images with their heatmaps. Figures go to `results/figures/`. Each heatmap is for the class the model predicted and is scaled to 0-1 per image. For example:

```
python -m src.gradcam mean --checkpoint checkpoints/cnn/best.pt
```

`demo/app.py` starts the Gradio demo for a checkpoint (`python demo/app.py --checkpoint checkpoints/cnn/best.pt`). It shows one real and one fake demo holdout image in random order, then reveals the true labels, the prediction and the Grad-CAM overlays. `demo/make_backup.py` saves the same outputs for all demo holdout images to `results/demo_backup/`, for use if the live app fails.

## Running on Google Colab

Use a GPU runtime (Runtime > Change runtime type). Run each block as a cell. Replace `<repo-url>` with the address of our repository and `<dataset folder>` with the folder under `data/raw` that contains `train/`, `valid/` and `test/`.

```
!git clone <repo-url> gan-face-detector
%cd gan-face-detector
!pip install -r requirements.txt
```

Upload your own `kaggle.json` (it is stored only in the Colab session):

```
from google.colab import files
files.upload()
!mkdir -p ~/.kaggle && mv kaggle.json ~/.kaggle/ && chmod 600 ~/.kaggle/kaggle.json
```

Download the data, build the manifest and run the audit:

```
!kaggle datasets download -d xhlulu/140k-real-and-fake-faces -p data/raw --unzip
!python src/data/build_manifest.py --root "<dataset folder>" --out data/manifest.csv
!python src/data/audit.py --manifest data/manifest.csv
```

Train one model. Start with a short run on a subset to check that everything works, then run on the full training split:

```
!python -m src.train --model cnn --epochs 2 --limit 2000
!python -m src.train --model cnn --epochs 10
```

Train the other models the same way (`--model cnn_resnet34`, `--model lstm --img-size 128`, `--model vit --lr 2e-5`), then compare:

```
!python -m src.compare
```

Colab deletes its files when the session ends, so copy `results/` and `checkpoints/` to Google Drive after each run:

```
from google.colab import drive
drive.mount('/content/drive')
!cp -r results checkpoints /content/drive/MyDrive/
```

A run with `--limit` is only a smoke test. Its results should not go into the report; the comparison table shows the number of training images used for each model so this is visible.
